# Feralin V21 — SDK Capability Matrix (26 platform)

**Tarih:** 3 Kasım 2026 · **Kaynak:** `feralin_proje_v21.md` §8.1 (platform listesi), §8.2 (UTP v1), §42 (Release & Registry Center; **faz ataması kanonik: mobil F3, Unity/oyun F4**), §45-A · **Durum:** 17 Kasım 2026'da 10 npm paketi `@feralin` organizasyonunda yayımlandı ve registry'den geri okundu (`@feralin/web`, `react`, `vue`, `angular`, `node`, `express`, `nest`, `react-native`, `electron`, `mcp-server`; ayrıntı `docs/sdk/npm-yayin-adimlari.md`). Öteki SDK'lar hiçbir registry'ye yayınlanmadı. Kod yazılmış SDK'ların hücreleri ve zincir tablosu (§7) `sdks/capabilities.yaml` dosyasından üretilir; test bu eşleşmeyi denetler. Kalan hücrelerdeki `PLANNED` hedeftir; parantezde `ÇALIŞTIRILMADI` yazmıyorsa o yetenek için kod yoktur. Paket adları (`@feralin/*`, `com.feralin:*` vb.) yalnız öneridir; namespace sahipliği doğrulanmadan kesin değildir (`BLOCKED_EXTERNAL`).

## 0. Okuma kılavuzu

- **Tier A:** tam resmî SDK, bakım verilir · **Tier B:** sınırlı/uyumlu adaptör · **Tier C:** REST/OpenAPI üzerinden (SDK kodu yok).
- **Faz:** §42.7 kanonik: F1 JS/TS + Go server client · F2 PHP/Python/.NET/Node server dalgası · F3 Swift/Kotlin/Flutter/RN · F4 Unity/Java/Rust/Ruby/C++/Unreal/Godot (+ Tier B kalanlar) · F5 purchase sözleşmeleri · F6 AI Installation Engineer · F7 LTS/EOL. §8.1'deki eski F2/F3 atamaları geçersizdir (§10 çelişki #2).
- **Capability sütunları** (`capabilities.yaml` ile birebir): `event` (track/page/screen), `batch` (batch/offline queue), `consent`, `identity` (identify/group/reset), `attribution` (platform köprüleri), `deeplink` (referral/deep link), `revenue` (trackRevenue + server verification), `error` (error/crash reporting), `replay` (session replay/heatmap, yalnız uygun platform), `tracing` (OTel context/diagnostics).
- **Hücre değerleri:** `PLANNED` (geliştirme hedefi; parantezde "ÇALIŞTIRILMADI" yazıyorsa kod vardır ama hiç koşmadı) · `SUPPORTED | PARTIAL | UNSUPPORTED | N/A`. `N/A` yalnız platform doğası gereği anlamsız olanlarda (ör. server SDK'da replay) işaretlendi ve bu da "yapılmayacak" kararıdır, mevcut özellik değil.
- **Yaşam döngüsü (§42.2):** `PROPOSED → IMPLEMENTING → UNIT_TESTED → INTEGRATION_TESTED → PLATFORM_TESTED → SECURITY_APPROVED → RELEASE_CANDIDATE → PUBLISHED → REGISTRY_VERIFIED → INSTALL_VERIFIED → SUPPORTED`. Her SDK'nın bugünkü değeri §7'dedir. `REGISTRY_VERIFIED` ve `INSTALL_VERIFIED` yalnız yayımlanan npm paketlerindedir; `SUPPORTED` yoktur (Super Admin kanıtı ve destek süresi yok).

## 3. Ortak sözleşme (tüm Tier A/B)

- **UTP v1:** `event_id`, `event_name`, `occurred_at`, `platform`, `schema_version=1`, `consent.analytics` zorunlu; `tenant_id`/`project_id`/`verified` istemciden kabul edilmez (`packages/schemas/utp/v1/event.schema.json`).
- **Client metotları:** `initialize, track, page, screen, identify, group, setConsent, flush, reset, optOut, getStatus, setUserProperties, setGlobalProperties, trackRevenue`.
- **Dayanıklılık:** retry exponential backoff + jitter, offline şifreli kuyruk (mobil/desktop), batch ≤ 500 event, idempotent `event_id`, pil/ağ sınırları, app lifecycle.
- **Gizlilik:** consent-first; `optOut` sonrası sıfır gönderim; PII redaksiyon allowlist; IDFA/GAID sunucuya gönderilmez; parmak izi yok.
- **Yayın:** semver, changelog, LICENSE, SBOM, imzalı artefact (destekleyen registry'lerde), OIDC trusted publishing (varsa), registry read-back, clean install, test event → ingest → dashboard, Super Admin kayıt. Erişim yoksa `BLOCKED_EXTERNAL`.
- **Dokümantasyon:** her SDK için `docs/sdk/<language>/` kurulum, örnek app, consent rehberi, uyumluluk matrisi; sihirbaz yalnız gerçek yayınlı sürümü gösterir.
